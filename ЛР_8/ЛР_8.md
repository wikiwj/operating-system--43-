## Відповіді на питання для попередньої підготовки

### 1. Що таке «псевдофайлова система», для чого вона потрібна системі?

**Pseudo filesystem** (псевдофайлова система) — це файлова система, файли й каталоги якої виглядають як звичайні, але фізично не зберігаються на диску. Вони існують лише в пам'яті й створюються ядром «на льоту» під час звернення.

Основні псевдофайлові системи Linux:

- `/proc`: інформація про процеси, апаратне забезпечення й поточну конфігурацію ядра;
- `/sys`: інформація про пристрої та драйвери;
- `/dev`: спеціальні файли пристроїв (у сучасних системах `devtmpfs`).

**Навіщо вона потрібна:**

- надає єдиний інтерфейс між ядром і користувацькими програмами: ядро «показує» свій стан у вигляді файлів, які можна читати стандартними інструментами (`cat`, `grep`, `less`);
- дозволяє переглядати стан системи в реальному часі без окремих системних викликів;
- дає змогу змінювати деякі параметри ядра на льоту (наприклад, записом у `/proc/sys/...`);
- не займає місця на диску.

### 2. Чому користувачі нечасто звертаються напряму до `/proc` і як отримати з нього інформацію?

Вміст `/proc` — це «сирі» дані ядра: тисячі файлів і підкаталогів, формат яких зручний машині, а не людині. Каталог `/proc` читають і обробляють самі утиліти, які подають дані в зручному вигляді. Наприклад:

| Команда | Що бере з `/proc` |
|---|---|
| `top`, `ps` | дані про процеси з `/proc/<PID>/...` |
| `free` | `/proc/meminfo` |
| `mount`, `umount` | `/proc/mounts` |
| `lsmod` | `/proc/modules` |
| `uptime` | `/proc/uptime`, `/proc/loadavg` |

Якщо потрібно, інформацію можна прочитати напряму:

```bash
cat /proc/cpuinfo
cat /proc/meminfo
ls /proc/1
```

Для кожного працюючого процесу в `/proc` є каталог із назвою, що збігається з його PID. У ньому лежать файли з описом конфігурації процесу, використання пам'яті тощо. У будь-якій працюючій системі завжди є процес із **PID 1** (у сучасних дистрибутивах це `systemd`).

### 3. Призначення `/proc/cmdline`, `/proc/meminfo`, `/proc/modules`

| Файл | Призначення |
|---|---|
| `/proc/cmdline` | параметри командного рядка, передані ядру під час завантаження (наприклад, `root=...`, `quiet`, `splash`) |
| `/proc/meminfo` | детальна інформація про використання пам'яті (загальна, вільна, buffers, cache, swap) |
| `/proc/modules` | список модулів ядра, завантажених у даний момент (драйвери й додаткові функції) |

### 4. Призначення команди `free`

Команда `free` показує **знімок використання пам'яті** на момент виконання: загальний обсяг, використану, вільну, спільну, buffers/cache, доступну RAM та swap. Дані беруться з `/proc/meminfo`.

Корисні параметри:

- `free -h`: вивід у зручних одиницях (Mi, Gi);
- `free -m`: в мегабайтах;
- `free -s 10`: оновлювати вивід кожні 10 секунд (моніторинг у часі);
- `free -s 2 -c 5`: оновити 5 разів з інтервалом у 2 секунди.

### 5. Для чого потрібні лог-файли, приклади застосування

**Log files** — це файли, в які ядро й процеси записують повідомлення про свою роботу. Не все виводиться на екран, тому більшість даних іде у файли, переважно в каталог `/var/log`.

**Застосування:**

- **Troubleshooting** (пошук несправностей): що пішло не так під час запуску служби; наприклад, `journalctl -u ssh`.
- **Security** (безпека): виявлення спроб неавторизованого доступу в `/var/log/auth.log` (на RHEL-подібних системах `secure`); перегляд невдалих входів командою `lastb`.
- **Audit** (аудит): хто й коли входив у систему (`last`, `/var/log/wtmp`).
- **Monitoring** (моніторинг): стеження за роботою cron, поштових і веб-сервісів.
- **Diagnostics hardware** (діагностика обладнання): повідомлення ядра про USB-пристрої, диски (`dmesg`).

Основні файли:

| File | Contents |
|---|---|
| `boot.log` | повідомлення при старті служб |
| `cron` | повідомлення демона cron |
| `dmesg` | повідомлення ядра під час завантаження |
| `maillog` | повідомлення поштового демона |
| `messages` (в Ubuntu `syslog`) | повідомлення ядра й інших процесів загального призначення |
| `secure` (в Ubuntu `auth.log`) | повідомлення про авторизацію й автентифікацію |
| `journal` | журнал `systemd-journald` |
| `Xorg.0.log` | повідомлення графічного сервера X |

Логи ротуються (**log rotation**): старі файли отримують суфікс із датою або номером (наприклад, `messages-20181103`), а запис продовжується в новий файл.

### 6. Призначення файлу `/var/log/dmesg`

У `/var/log/dmesg` зберігаються **повідомлення ядра, створені під час запуску системи**: виявлення обладнання, завантаження драйверів, ініціалізація пристроїв. Повідомлення ядра під час роботи системи потрапляють у `/var/log/messages` (в Ubuntu `/var/log/syslog`) разом із повідомленнями демонів.

Команда `dmesg` читає **kernel ring buffer** — кільцевий буфер повідомлень ядра. Його розмір фіксується при компіляції ядра, тому при великій кількості повідомлень старі можуть втрачатися. Вивід `dmesg` може сягати 512 КБ, тому його варто фільтрувати:

```bash
dmesg | less
dmesg | grep -i usb
```

### 7. Для чого розроблено FHS?

**Filesystem Hierarchy Standard (FHS)** — стандарт Linux Foundation, який визначає рекомендовану структуру каталогів у Linux-системах та призначення кожного з них.

Навіщо він потрібен:

- забезпечує **єдиний підхід до організації файлів** у різних дистрибутивах;
- програмісти й адміністратори знають, де шукати конфігурацію, програми й логи;
- полегшує розробку програмного забезпечення, сумісного з різними дистрибутивами;
- класифікує каталоги за двома ознаками:
  - **shareable / unshareable**: чи можна каталог спільно використовувати в мережі (наприклад, `/var/mail` shareable, `/var/lock` ні);
  - **static / variable**: чи змінюється вміст (`/usr` static, `/var` variable).

FHS є рекомендацією, а не жорстким законом, тому окремі дистрибутиви й адміністратори можуть відхилятися від нього.

### 8. Основні команди для перегляду та конфігурації мережі

| Команда | Призначення |
|---|---|
| `ifconfig` | перегляд і налаштування мережевих інтерфейсів (застаріла) |
| `ip` | універсальна заміна `ifconfig`, `route`, `arp`; наприклад, `ip addr show` |
| `route` / `ip route` | перегляд таблиці маршрутизації |
| `ping` | перевірка доступності іншого вузла |
| `traceroute` | відстеження шляху пакетів до вузла |
| `netstat` | з'єднання, таблиця маршрутизації, статистика (застаріла) |
| `ss` | статистика сокетів, заміна `netstat` |
| `dig` | запити до DNS-сервера |
| `host` | зіставлення імені хоста й IP-адреси |
| `ssh` | віддалений вхід на іншу машину |
