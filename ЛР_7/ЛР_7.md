## 2. Відповіді на питання для попередньої підготовки

### 4.1. Поняття скриптового сценарію у командній оболонці

**Скриптовий сценарій (shell script)** - це текстовий файл, у якому записано послідовність команд командної оболонки. Під час запуску файлу команди виконуються по черзі, так само, як якби користувач вводив їх у терміналі вручну.

Особливості та призначення скриптів:

* скрипт має доступ до всіх команд оболонки, а також до **логіки**: він може перевіряти наявність файлу, аналізувати вивід команди та змінювати свою поведінку;
* дозволяє **автоматизувати** повторювані дії: якщо щодня виконується однаковий набір із п'яти команд, його можна звести до одного виклику;
* гарантує **однаковий результат** при кожному запуску, зменшує кількість помилок і економить час;
* не потребує компіляції: код виконує інтерпретатор (`sh`, `bash`).

Найпростіший скрипт складається з однієї команди:

```bash
echo "Hello, World!"
```

Для складніших скриптів у **першому рядку** вказують інтерпретатор, що виконуватиме код (рядок «shebang»):

```bash
#!/bin/bash
echo "Hello, World!"
```

Основні елементи, з якими необхідно познайомитися при написанні скриптів:

| Елемент | Призначення | Приклад |
| --- | --- | --- |
| Змінні (variables) | зберігають тимчасову інформацію у скрипті | `NAME="student"`, звернення: `$NAME` |
| Умови (conditionals) | виконують різні дії залежно від результату перевірки | `if [ -f /etc/passwd ]; then ... fi` |
| Цикли (loops) | багаторазово виконують однакові дії | `for i in 1 2 3; do ... done` |

Приклад скрипта з усіма трьома елементами:

```bash
#!/bin/bash
NAME="student"                          - змінна
echo "Hello, $NAME!"
if [ -f /etc/passwd ]; then             - умова
    echo "File /etc/passwd exists"
else
    echo "File not found"
fi
for i in 1 2 3; do                      - цикл
    echo "Iteration $i"
done
```

### 4.2. Створення, редагування та запуск скриптів

**Створення і редагування.** Скрипт - це звичайний текстовий файл, тому його створюють у будь-якому текстовому редакторі. У курсі розглядається редактор **nano**: простий, зручний для невеликих файлів. Другий поширений редактор - **vi** (його нова версія **vim**) - дуже потужний, але складніший у вивченні.

Створити файл і відкрити його для редагування:

```bash
nano test.sh
```

У редакторі текст вводиться з клавіатури, для переміщення використовуються стрілки, для видалення - `Delete` / `Backspace`. Внизу екрана відображається підказка з комбінаціями клавіш (`^` означає клавішу `Ctrl`).

| Комбінація | Дія |
| --- | --- |
| `Ctrl + O` | зберегти файл, не виходячи з редактора |
| `Ctrl + X` | вийти з редактора (запропонує зберегти зміни: `Y` - зберегти, `N` - не зберігати, `Ctrl + C` - скасувати) |
| `Ctrl + K` | вирізати поточний рядок у буфер |
| `Ctrl + U` | вставити вміст буфера |
| `Ctrl + W` | пошук по документу |
| `Ctrl + W`, потім `Ctrl + R` | пошук і заміна |
| `Ctrl + G` | показати довідку з усіма командами |
| `Ctrl + Y` / `Ctrl + V` | сторінка вгору / вниз |
| `Ctrl + C` | показати поточну позицію у файлі та розмір файлу |

**Що потрібно зробити, щоб запустити скрипт.** Є два способи:

1. **Передати скрипт як аргумент оболонці.** Права на виконання при цьому не потрібні:

```bash
sh test.sh
bash test.sh
```

2. **Запустити скрипт безпосередньо.** Для цього файлу потрібно надати право на виконання, а при запуску вказати шлях до файлу. Каталог `./` рідко входить до змінної `$PATH`, тому перед ім'ям файлу ставлять префікс `./`:

```bash
chmod +x test.sh      - дозволити виконання
./test.sh             - запустити з поточного каталогу
```

Якщо запустити файл без права на виконання, оболонка видасть помилку `Permission denied`.

Рядок `#!/bin/bash` (shebang) враховується лише при **прямому запуску**. Якщо скрипт передано як аргумент (`sh script` або `bash script`), буде використано саме вказаний інтерпретатор, незалежно від першого рядка файлу.

Кроки для запуску скрипта: створити файл (`nano`), записати команди та shebang, зберегти (`Ctrl+O`), вийти (`Ctrl+X`), надати право на виконання (`chmod +x`), запустити (`./test.sh`).

| Компонент | Призначення |

| Роз'єми передньої панелі (front panel header) | підключення кнопок живлення, індикаторів, USB та аудіо корпусу |
| Роз'єми вентиляторів (FAN) | підключення системи охолодження |

### 4.4. Поняття MBR та GPT

**MBR** та **GPT** - це два стандарти (схеми) **розмітки накопичувачів даних**, тобто способу зберігання таблиці розділів. Вони використовуються для жорстких дисків (HDD), твердотільних накопичувачів (SSD) та флешок.

**MBR (Master Boot Record)** - класична схема, що з'явилася у 1980-х роках і використовується разом із BIOS. Запис розташований у першому секторі диска (512 байт) і містить:

* завантажувальний код (446 байт);
* таблицю розділів (64 байти), що описує не більше **4 основних розділів** (або 3 основних і 1 розширений із логічними дисками всередині);
* сигнатуру (2 байти).

Обмеження: максимальний розмір диска - близько **2 ТБ**; уся інформація зберігається в одному місці, тому при пошкодженні першого сектора дані про розділи втрачаються.

**GPT (GUID Partition Table)** - сучасна схема, частина стандарту UEFI. Використовує 64-бітну адресацію секторів, кожен розділ отримує унікальний ідентифікатор GUID. Особливості:

* дуже велика кількість розділів (зазвичай до 128), без поділу на основні та розширені;
* підтримка дисків розміром у **десятки ТБ і більше** (теоретично до 9,4 ЗБ);
* копія таблиці розділів зберігається в кінці диска, що підвищує надійність;
* контрольні суми CRC для перевірки цілісності таблиці;
* у першому секторі розміщується «захисний MBR» (protective MBR) для сумісності зі старим ПЗ.

| Критерій | MBR | GPT |
| --- | --- | --- |
| Прошивка для завантаження | BIOS (Legacy) | UEFI (BIOS можливий лише за наявності спеціального розділу) |
| Максимальний розмір диска | ~2 ТБ | понад 2 ТБ (до 9,4 ЗБ) |
| Кількість розділів | 4 основних (або 3 + розширений) | до 128 (за замовчуванням) |
| Резервна копія таблиці розділів | немає | є (в кінці диска) |
| Перевірка цілісності | немає | є (CRC32) |
| Ідентифікація розділів | коди типів | унікальні GUID |

### 4.5. Суть операції монтування та її призначення

**Монтування (mounting)** - це операція підключення файлової системи пристрою або розділу (флешки, жорсткого диска, DVD, ISO-образу, мережевої папки) до єдиного дерева каталогів ОС через певний каталог, який називається **точкою монтування (mount point)**.

У Linux немає дисків із літерами (`C:`, `D:`), як у Windows. Існує одне дерево каталогів із коренем `/`, а всі розділи та носії стають його частиною. Поки файлову систему не змонтовано, у системі є лише «сирий» файл пристрою (наприклад, `/dev/sdb1`), а вміст носія недоступний. Після монтування файли пристрою відображаються всередині точки монтування, і з ними можна працювати як зі звичайним каталогом.

**Для чого потрібне монтування:**

* надає доступ до даних на носії незалежно від його типу та файлової системи;
* дозволяє розділити систему на частини (наприклад, `/home`, `/var`, `/boot` на окремих розділах);
* дозволяє задавати режими доступу: лише читання (`ro`), заборона запуску програм (`noexec`) тощо;
* дозволяє підключати мережеві ресурси (NFS, Samba/CIFS) так, ніби вони розташовані локально.

**Як виконується монтування:**

```bash
lsblk                              # визначити ім'я пристрою
sudo mkdir -p /mnt/usb             # створити точку монтування
sudo mount /dev/sdb1 /mnt/usb      # змонтувати
ls /mnt/usb                        # працювати з файлами
sync                               # скинути кеш на носій
sudo umount /mnt/usb               # відмонтувати перед вилученням
```

Відмонтування обов'язкове перед фізичним вилученням носія, оскільки частина даних може залишатися в кеші пам'яті та не бути записаною. Для автоматичного монтування під час завантаження системи використовується файл `/etc/fstab`. Переглянути змонтовані файлові системи можна командами `mount`, `findmnt` та `df -h`.
