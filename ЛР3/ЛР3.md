### 1. Vocabulary of Basic English Terms

* **Command Line Interface (CLI)** – інтерфейс командного рядка.
* **Shell** – командна оболонка.
* **Prompt** – командне запрошення.
* **Command** – інструкція для операційної системи.
* **Option** – параметр команди.
* **Argument** – об'єкт, над яким виконується дія.
* **Variable** – використовується для зберігання даних.
* **Alias** – коротка назва для довгої команди.
* **Built-in command** – внутрішня команда оболонки.
* **Environment** – середовище виконання.

### 4. Definitions

* **Command line interpreter:** program, яка читає user commands та передає їх на виконання OS.
* **Shell:** text-based interface між user та OS kernel.
* **Command:** software instruction комп'ютеру для виконання specific action на CLI.

### 5. Контрольні запитання

1. ### Яку базову інформацію надає рядок запрошення prompt?
   
   **Prompt** надає basic information: Username, System/Host name та Current Directory.

2. ### Для чого команді потрібні параметри та аргументи? 
   
   **Options** змінюють або доповнюють command behavior. **Arguments** вказують на target object дії команди (наприклад, specific file).

3. ### Яке призначення команд ls, які параметри та аргументи вона може мати? Наведіть 3 приклади.
   
   Команда **`ls`** виводить інформацію про directories та files.
   * *Приклад 1:* `ls` (показує вміст current directory).
   * *Приклад 2:* `ls /etc/ppp` (показує вміст specific directory).
   * *Приклад 3:* `ls -l` (показує детальний список у long format).

4. ### Яким чином можна використати історію команд, які переваги це надає?

    **Command line history** дозволяє переглядати previous commands за допомогою клавіш вгору/вниз або команди `history`. Вона дозволяє re-run commands без re-typing, що saves time та reduces errors.

5. ### Яке призначення команди echo?

    Команда **`echo`** виводить text або variable values на terminal screen.

6. ### Охарактеризуйте поняття змінної в оболонці Bash, які типи змінних вона підтримує? 

    **Variable** дозволяє user або shell тимчасово зберігати дані. Вона підтримує два типи: local та environment variables.

7. ### Яке призначення команд env, export та unset?
   
    **Command purposes:**
   * `env` - виводить current environment variables.
   * `export` - робить local variable доступною для child processes, перетворюючи її на environment variable.
   * `unset` - видаляє змінну з пам'яті.

8. ### Які команди для отримання довідки по командам в терміналі ви знаєте?
    Для **getting help** по командам використовують `man` (manual pages), `info`, а також `--help` (або `-h`).

### 1. Commands Table

| Command | Purpose and Functionality | 
| ----- | ----- | 
| `ls` | Ця command виводить список files та directories. Без додаткових options та arguments, вона показує вміст вашої current directory. Це базовий інструмент для швидкого перегляду вмісту file system. | 
| `ls -l` | Додавання -l option змінює формат виводу на long format. Ви побачите detailed information: розмір (size), права доступу (permissions), власника (owner) та date of creation для кожного файлу. | 
| `ls -l /tmp` | Використання -l option разом із /tmp argument вказує системі показати detailed information у long format для specific directory /tmp, не змінюючи при цьому вашу current directory. | 
| `pwd` | Print Working Directory - ця command виводить full absolute path до вашого поточного робочого каталогу. Вона допомагає зрозуміти ваше точне location у file hierarchy операційної системи. | 
| `cd` | Change Directory - команда для зміни current directory. Дозволяє здійснювати навігацію (navigation) по system, переходячи між папками за допомогою relative або absolute paths. | 
| `echo` | Prints text або вміст variable values на екран (standard output). Це дуже корисно при написанні scripts для виведення повідомлень або перевірки значень environment variables. | 
| `type` | Ця command показує command type. Вона допомагає зрозуміти, як система обробляє команду: чи це built-in command самої оболонки, external file чи створений користувачем alias. | 
| `history` | Відображає нумеровану command history (історію раніше введених команд). Це дозволяє легко знаходити попередні actions та re-run commands без необхідності їх повторного введення вручну. | 
| `man` | Відкриває Manual page (офіційну довідку) для вказаної команди. Вона містить in-depth documentation про всі можливі options, arguments, а також надає приклади використання команди. |

### 2.3. Робота з лапками (Quoting) в терміналі

У Bash одинарні лапки `' '` повністю вимикають спеціальне значення символів (`$var_name1` буде виведено як текст), а подвійні лапки `" "` дозволяють підстановку змінних та команд (`"$var_name1"` буде замінено на вміст змінної). Це дозволяє в одному реченні поєднати і назви змінних, і їх вміст.

**Речення 1:** спочатку виводимо назви змінних, потім їх вміст.

```bash
echo 'We create such variables as $var_name1, $var_name2, $var_name3, which stored our names' "$var_name1, $var_name2, $var_name3"
```

Очікуваний результат:

```text
We create such variables as $var_name1, $var_name2, $var_name3, which stored our names Name1 Surname1, Name2 Surname2, Name3 Surname3
```

**Речення 2:** спочатку виводимо назви псевдонімів, потім вивід цих команд.

Вивід псевдоніма отримуємо за допомогою підстановки команди `$(...)` (або зворотних лапок `` ` ` ``) у подвійних лапках, щоб зберегти розбиття календаря на рядки.

```bash
echo 'We create such Aliases as mycal1, mycal2, mycal3, which can show our calendars:'
echo "$(mycal1)"
echo "$(mycal2)"
echo "$(mycal3)"
```

Якщо в підстановці команди псевдонім не розкривається, замість нього можна використати сам вираз, на який він посилається:

```bash
echo "$(cal 2008)"
```

### 2.4. Робота з інструкціями керування (Control Statements) в терміналі

**Чи можна завдання 2.1 та 2.2 виконати через інструкції керування без написання окремої функції?**

Так, можна. Інструкції керування `;`, `&&` та `||` дозволяють виконати кілька команд в одному рядку, тому функція не є обов'язковою.

| Інструкція | Дія |
| --- | --- |
| `;` | Команди виконуються послідовно, незалежно від результату попередньої |
| `&&` | Наступна команда виконується, лише якщо попередня завершилась успішно |
| `\|\|` | Наступна команда виконується, лише якщо попередня завершилась з помилкою |

**Завдання 2.1 через інструкції керування один рядок:**

```bash
var_name1="Name1 Surname1"; var_name2="Name2 Surname2"; var_name3="Name3 Surname3"; echo $var_name1; echo $var_name2; echo $var_name3; alias mycal1='cal 2006'; alias mycal2='cal 2006'; alias mycal3='cal 2007'
```

**Завдання 2.2 через інструкції керування один рядок:**

```bash
var_year1=2006; var_year2=2006; var_year3=2007; echo "$var_name1"; echo "$var_name2"; echo "$var_name3"; echo "$var_year1"; echo "$var_year2"; echo "$var_year3"
```

**Варіант з `&&`** кожна наступна команда виконається, лише якщо попередня пройшла успішно:

```bash
var_name1="Name1 Surname1" && var_name2="Name2 Surname2" && var_name3="Name3 Surname3" && echo "$var_name1" && echo "$var_name2" && echo "$var_name3"
```

**Варіант з `||`** повідомлення виведеться, лише якщо змінна порожня:

```bash
[ -n "$var_name1" ] || echo "Змінна var_name1 не задана"
```

**Різниця між підходами:**

- **Функція** записується один раз і викликається за іменем `students_report` скільки завгодно разів у сеансі.
- **Інструкції керування** потрібно вводити повністю щоразу, але вони не потребують створення окремої конструкції, а рядок зручно вставляти або зберігати у скрипті.

### 2.5. Робота з командами довідки (Man Pages) в терміналі

**Отримання довідки на прикладі команди `uname`** команда виводить інформацію про систему.

Основні способи отримати довідку:

```bash
man uname          # повна сторінка посібника (для виходу натисніть q)
uname --help       # коротка довідка з переліком параметрів
whatis uname       # однорядковий опис команди
info uname         # довідка у форматі info
```

Під час перегляду `man uname`: **пробіл** - наступна сторінка, **b** - назад, **/текст** - пошук, **n** - наступний збіг, **q** - вихід.

**5 варіантів виводу команди `uname` з різними параметрами (Options):**

| № | Команда | Що виводить |
| --- | --- | --- |
| 1 | `uname -s` | Назву ядра операційної системи (kernel name) |
| 2 | `uname -n` | Мережеве ім'я вузла (hostname) |
| 3 | `uname -r` | Випуск (версію) ядра (kernel release) |
| 4 | `uname -m` | Архітектуру процесора (machine hardware name) |
| 5 | `uname -a` | Уся інформація одним рядком (all) |

Приклад виконання:

```bash
uname -s
uname -n
uname -r
uname -m
uname -a
```

Приклад результату :

```text
Linux
debian
6.1.0-25-amd64
x86_64
Linux debian 6.1.0-25-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.1.106-3 (2024-08-26) x86_64 GNU/Linux
```


# Єршов Олексій

1. ### Які типи команд існують в оболонці Bash?
   
   У Bash є кілька основних типів команд: **вбудовані команди** оболонки, наприклад `cd`, `echo`, `pwd`; **зовнішні програми** та утиліти, наприклад `ls` або `grep`; **аліаси** та **функції**. Вбудовані команди виконуються самим Bash, а зовнішні програми запускаються як окремі процеси.

2. ### Що таке змінні оточення? Які вони бувають? Як їх можна переглянути в терміналі?
   
   Змінні оточення містять інформацію про середовище, у якому працюють програми: наприклад, шляхи до програм, ім'я користувача, домашню директорію тощо. Є **звичайні** змінні оболонки та змінні, які були **експортовані** й тому передаються дочірнім процесам. Переглянути змінні оточення можна за допомогою команд `env` або `printenv`.

3. ### Опишіть змінну $PS1. Як в терміналі переглянути її вміст?
   
   Змінна `$PS1` визначає вигляд основного запрошення Bash - рядка, який ми бачимо перед введенням команди (prompt). У ньому можна, наприклад, показувати ім'я користувача, назву комп'ютера або поточну директорію. Переглянути значення змінної можна командою:
   `echo $PS1`

4. ### Як можна змінити значення змінної $PS1? Що при цьому відбудеться в рядку запрошення Bash? Як змінити значення цієї змінної за замовчуванням?
   
   Значення можна змінити звичайним присвоєнням, наприклад:
   `PS1="my_shell> "`
   Після цього в поточному сеансі Bash запрошення зміниться на `my_shell>`. Після закриття терміналу ця зміна не збережеться.
   Щоб встановити таке значення для наступних сеансів Bash, рядок можна додати до файлу `~/.bashrc`. Після цього зміни можна застосувати командою:
   `source ~/.bashrc`
   Для зміни `$PS1` саме в Bash використовувати `export` не обов'язково.

5. ### Для чого використовують лапки в оболонці Bash?
   
   Лапки використовують, зокрема, коли потрібно зберегти пробіли в тексті або запобігти небажаній інтерпретації спеціальних символів.
   * **Одинарні лапки** (`' '`) сприймають текст усередині буквально. Наприклад, змінна всередині одинарних лапок не розкривається.
   * **Подвійні лапки** (`" "`) дозволяють виконувати підстановку змінних. Наприклад, `"Привіт, $USER"` міститиме значення змінної `$USER`. Для підстановки результату команди використовують конструкцію `$(команда)`.

6. ### Для чого використовують інструкції керування? Які їх види ви знаєте?
   
   Інструкції керування потрібні для побудови логіки Bash-скриптів. За їх допомогою можна перевіряти умови та повторювати певні команди.
   До основних конструкцій належать **умовні оператори** `if` та `case`, а також **цикли** `for`, `while` і `until`.

7. ### В чому різниця, якщо в кінці рядка запрошення Bash стоїть символ $ чи #?
   
   Це поширене позначення в командному рядку. Символ **`$`** зазвичай використовують для звичайного користувача, а **`#`** - для користувача root. Однак це лише стандартна домовленість оформлення prompt: сам символ автоматично не визначає права користувача.

8. ### Яке призначення команд whereis та locate? Яка між ними відмінність?
   
   Обидві команди використовують для пошуку, але вони мають різне призначення:
   * **`whereis`** призначена для пошуку пов'язаних із програмою файлів, зокрема виконуваних файлів, вихідного коду та сторінок довідки man.
   * **`locate`** використовується для швидкого пошуку файлів за їхніми назвами. Для цього вона використовує заздалегідь створену базу даних, тому пошук відбувається швидше, ніж повний пошук файлової системи. Якщо файл був створений нещодавно, його може не бути в результатах, доки база не буде оновлена, наприклад за допомогою команди `updatedb`.
