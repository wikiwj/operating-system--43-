1. Для чого використовують Git і які основні дії там виконують
Git - це система контролю версій (version control system). Вона потрібна, щоб:

+ відстежувати історію змін у файлах проєкту (хто, коли і що змінював); 
+ працювати над проєктом кільком людям одночасно, не заважаючи одне одному;
+ мати можливість повернутися до будь-якої попередньої версії коду;
+ працювати з різними "гілками" розробки (наприклад, тестувати нову фічу окремо від стабільної версії);
+ зберігати проєкт віддалено (на GitHub/GitLab) і синхронізувати його між комп'ютерами та учасниками команди.

Робочий процес у Git ділиться на три етапи:

+ Робоча директорія (Working Directory). Твої файли на диску, де ти пишеш код.
+ Область підготовки (Staging Area). Буфер, куди ти додаєш файли перед збереженням.
+ Сховище (Repository). База даних, куди записуються готові точки збереження.

Основні команди:

```
git init //створити новий git-репозиторій у папці
```
```
git clone <url> // завантажити (склонувати) наявний репозиторій
```
```
git status // подивитися, які файли змінені
```
```
git add . // додати всі змінені файли в індекс (підготувати до коміту)
```
```
git commit -m "текст" // зафіксувати зміни (створити коміт)
```
```
git push // відправити коміти на віддалений сервер (GitHub/GitLab)
```
```
git pull // забрати зміни з віддаленого сервера
```
```
git log // подивитися історію комітів
```
```
git branch // подивитися існуючі гілки або створити нову
```
```
git checkout <гілка> // переключитися на іншу гілку
```
```
git merge <гілка> // об'єднати вказану гілку з поточною
```
```
git switch <назва> // перейти на іншу існуючу гілку
```
```
git diff // подивитися точні правки в коді до збереження
```
```
git fetch // лише перевірити та завантажити оновлення з сервера без злиття
```
```
git log --oneline // вивести скорочений список попередніх дій
```
```
git revert <хеш> // створити зворотну дію для скасування зазначеного запису
```
```
git stash // сховати тимчасові незавершені правки
```
```
git stash pop // дістати сховані правки назад у роботу
```
```
git blame <файл> // показати автора і коміт для кожного рядка у файлі
```

2.Що таке "коміт" ?

Коміт (commit) - це "знімок" (снапшот) стану файлів проєкту в певний момент часу, зафіксований з описом зроблених змін. 

Складові частини коміту:

+ Хеш ідентифікатор. Унікальний рядок символів на основі алгоритму SHA, який слугує номером запису в базі.
+ Авторські дані. Імʼя та електронна пошта розробника.
+ Часова мітка. Дата і точний час збереження.
+ Коментар (commit message). Текстове пояснення суті змін.
+ Посилання на попередній запис (parent). Повʼязує збереження в єдиний ланцюг подій.

Як це допомагає відстежувати зміни:

+ Кожен коміт зберігає різницю (diff) між попереднім станом файлів і новим - тобто видно, що саме додали, видалили чи змінили.
+ У кожного коміту є автор, дата і повідомлення (commit message), де описано, що було зроблено і навіщо.
+ Коміти вибудовуються в ланцюжок (історію), тому можна побачити весь шлях розвитку проєкту - `git log` покаже всі коміти по порядку.
+ Якщо щось пішло не так, можна повернутися до будь-якого з попередніх комітів (`git checkout <hash>` або `git revert`).
+ Коли над проєктом працюють кілька людей, по комітах видно, хто саме і що змінював - це важливо для пункту 4 завдання (коміти від кожного учасника команди).
