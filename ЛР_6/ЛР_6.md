### 5.1. Призначення команд tar, xz, zip, bzip2, gzip

| Команда | Призначення | Основні параметри | Встановлення |
| --- | --- | --- | --- |
| `tar` | Об'єднує багато файлів і каталогів в один архівний файл (`.tar`) зі збереженням прав доступу та структури. Сам по собі не стискає, але може викликати `gzip`, `bzip2` або `xz` | `-c` - створити архів; `-x` - витягти; `-t` - переглянути вміст; `-r` - додати файл до архіву; `-v` - докладний вивід; `-f` - ім'я файлу архіву; `-z` - стиснення gzip; `-j` - стиснення bzip2; `-J` - стиснення xz | Зазвичай уже встановлена. Якщо ні: `sudo apt install tar` |
| `gzip` / `gunzip` | «Класичне» швидке стиснення (алгоритм DEFLATE), файли отримують розширення `.gz`. Оригінал замінюється стисненим файлом | `-d` - розпакувати (як `gunzip`); `-r` - рекурсивно; `-l` - статистика стисненого файлу; `-c` - вивід у `stdout`; `-1`...`-9` - рівень стиснення (за замовчуванням `-6`) | Зазвичай уже встановлена. Якщо ні: `sudo apt install gzip` |
| `bzip2` / `bunzip2` | Стискає краще за `gzip`, але повільніше та з більшим споживанням пам'яті (алгоритм Burrows-Wheeler), розширення `.bz2` | `-d` - розпакувати (як `bunzip2`); `-s` - режим зменшеного використання пам'яті; `-1`...`-9` - розмір блоку (за замовчуванням `-9`); `-k` - залишити оригінал | `sudo apt install bzip2` |
| `xz` / `unxz` | Найкраще стиснення (алгоритм LZMA2), але найповільніше і з найбільшою витратою пам'яті; швидко розпаковується; розширення `.xz` | `-d` - розпакувати (як `unxz`); `-l` - статистика; `-c` - вивід у `stdout`; `-0`...`-9` - рівень стиснення (за замовчуванням `-6`); `-e` - «екстремальний» режим | `sudo apt install xz-utils` |
| `zip` / `unzip` | Створює архів зі стисненням (формат `.zip`), сумісний з Windows. На відміну від `gzip`, оригінал залишається | `zip -r` - рекурсивно додавати каталоги; `zip -e` - захист паролем; `unzip -l` - переглянути вміст; `unzip -d` - каталог для розпакування | `sudo apt install zip unzip` |

### 5.2. Приклади архівування та стискання даних різними командами

**Приклад 1. Архів `tar` зі стисненням gzip**

```bash
tar -zcvf backup.tar.gz /etc/udev     - створити
tar -xzvf backup.tar.gz               - розпакувати
```

**Приклад 2. Стискання окремого файлу за допомогою xz**

```bash
xz words                              - створює words.xz, оригінал видаляється
unxz words.xz                         - відновлює words
```

**Приклад 3. Архів `zip` для передачі користувачам Windows**

```bash
zip -r udev.zip /etc/udev             - створити архів з каталогом
unzip -l udev.zip                     - переглянути вміст
unzip udev.zip                        - розпакувати
```

Додатково: `tar -jcvf backup.tar.bz2 dir/` створює архів, стиснений за допомогою bzip2.

### 5.4. Принципи роботи командної оболонки з потоками, каналами та фільтрами

**Потоки.** Кожна програма в Linux при запуску отримує три стандартні потоки:

| Потік | Дескриптор | Призначення | За замовчуванням |
| --- | --- | --- | --- |
| `stdin` | 0 | стандартне введення | клавіатура |
| `stdout` | 1 | стандартне виведення | екран терміналу |
| `stderr` | 2 | стандартний потік помилок | екран терміналу |

**Перенаправлення.** Оболонка Bash може замінити джерело або приймач потоку:

| Запис | Дія |
| --- | --- |
| `cmd > file` | вивід `stdout` записується у файл (вміст перезаписується) |
| `cmd >> file` | вивід додається в кінець файлу |
| `cmd < file` | `stdin` береться з файлу |
| `cmd 2> file` | помилки (`stderr`) записуються у файл |
| `cmd &> file` | і `stdout`, і `stderr` - у файл |
| `cmd 2> /dev/null` | помилки відкидаються |

**Канали (pipe).** Символ `|` з'єднує `stdout` однієї команди зі `stdin` іншої: `cmd1 | cmd2`. Так із простих команд будують складні ланцюжки без проміжних файлів. Звичайний канал передає лише `stdout`; щоб передати ще й помилки, використовують `cmd1 2>&1 | cmd2`.

**Фільтри.** Це команди, які читають дані зі `stdin`, змінюють або відбирають їх і виводять у `stdout` (наприклад, `sort`, `grep`, `wc`, `head`, `tail`, `cut`, `uniq`). Завдяки каналам їх можна комбінувати:

```bash
cat myfile | grep student | wc -l      - скільки рядків містять слово «student»
```

### 5.5. Призначення команди grep

**`grep`** (global regular expression print) - це фільтр, який шукає у файлах або у вхідному потоці рядки, що відповідають заданому шаблону (тексту чи регулярному виразу), і виводить ці рядки.

Синтаксис: `grep [параметри] шаблон [файл...]`

| Параметр | Дія |
| --- | --- |
| `-i` | ігнорувати регістр символів |
| `-v` | вивести рядки, які **не** містять шаблон |
| `-n` | показати номери рядків |
| `-c` | вивести лише кількість рядків-збігів |
| `-w` | шукати лише ціле слово |
| `-r` | рекурсивний пошук у каталозі |
| `-l` | вивести лише імена файлів, у яких є збіг |
| `-E` | розширені регулярні вирази (`egrep`) |
| `--color` | підсвітити знайдений текст |

Приклад: `grep -in "root" /etc/passwd` - знайти рядки зі словом «root» без урахування регістру та показати їх номери.

| `rm -r etc` | Рекурсивне видалення каталогу `etc` з усім вмістом (створеного після розпакування `tar`) перед розпакуванням `zip`-архіву |
| `unzip udev.zip` | Розпакування `zip`-архіву в поточний каталог (без додаткових параметрів). Відновлюються каталоги та файли `etc/udev/...` |

### Опис команд Lab 10: Working With Text

| Назва команди | Її призначення та функціональність |
| --- | --- |
| `echo "Hello World"` | Виводить текст у стандартний потік виведення (`stdout`), тобто на екран терміналу |
| `echo "Hello World" > mymessage` | Перенаправляє `stdout` у файл `mymessage` за допомогою символу `>`. Замість екрана текст потрапляє у файл (файл створюється, якщо його немає) |
| `cat mymessage` | Виводить вміст файлу `mymessage` на екран; використовується для перевірки результату перенаправлення |
| `echo "Greetings" > mymessage` | Повторне перенаправлення в той самий файл: символ `>` спочатку знищує вміст файлу, тому старий текст замінюється новим (так зване «clobbering») |
| `echo "How are you?" >> mymessage` | Символ `>>` дописує текст у кінець файлу, зберігаючи наявні дані |
| `find ~ -name "*bash*"` | Пошук файлів у домашньому каталозі (`~`) та всіх його підкаталогах, ім'я яких містить `bash`. Параметр `-name` задає шаблон імені. Знайдено `.bash_logout` і `.bashrc` |
| `find /etc -name hosts` | Пошук файлу `hosts` у каталозі `/etc`. Поряд із результатом `/etc/hosts` виводиться повідомлення `Permission denied` для каталогу, до якого звичайний користувач не має доступу. Такі повідомлення надходять у потік помилок `stderr`, а не в `stdout` |
| `find /etc -name hosts 2> err.txt` | Перенаправляє потік помилок `stderr` (дескриптор 2) у файл `err.txt`. На екрані залишається лише результат пошуку |
| `cat err.txt` | Перегляд повідомлень про помилки, що збережені у файлі `err.txt` |
| `find /etc -name hosts > std.out 2> std.err` | Перенаправлення `stdout` і `stderr` у два різні файли: результат пошуку - у `std.out`, повідомлення про помилки - у `std.err`. Пробіл після символу `>` дозволений, але не обов'язковий |
| `cat std.err` | Перегляд вмісту файлу з повідомленнями про помилки |
| `cat std.out` | Перегляд вмісту файлу з результатом пошуку (`/etc/hosts`) |
| `find /etc -name hosts > find.out 2>&1` | Перенаправлення і `stdout`, і `stderr` в один файл `find.out`. Запис `2>&1` означає «надіслати `stderr` (канал 2) туди, куди йде `stdout` (канал 1)» |
| `cat find.out` | Перегляд файлу `find.out`: у ньому разом зібрані і результат, і повідомлення про помилку |
| `tr a-z A-Z` | Команда `tr` замінює символи: тут малі літери на великі. Приймає дані лише зі `stdin` (клавіатури), а не з імені файлу. Введений рядок одразу виводиться у верхньому регістрі. Завершення введення - `Ctrl+D` (`^D`) |
| `tr A-Z a-z > myfile` | Перетворює введений з клавіатури текст на малі літери та перенаправляє вивід у файл `myfile`. Введення завершується натисканням `Enter` і `Ctrl+D` |
| `cat myfile` | Перегляд вмісту файлу `myfile` (текст, записаний малими літерами) |
| `tr a-z A-Z < myfile` | Перенаправлення стандартного введення: символ `<` передає вміст файлу `myfile` на `stdin` команди `tr`, яка виводить його великими літерами |
| `ls -l /etc \| more` | Канал (pipe): вивід команди `ls -l /etc` передається на вхід команди `more`, яка показує його посторінково. Продовжити перегляд - `Пробіл`, вийти - `Ctrl+C` |
| `cut -d: -f1 /etc/passwd` | Виділяє поля з рядків файлу. Параметр `-d:` задає роздільник полів (двокрапка), `-f1` - вивести перше поле. У результаті виводяться імена всіх користувачів із файлу `/etc/passwd` у неупорядкованому вигляді |
| `cut -d: -f1 /etc/passwd \| sort` | Вивід `cut` передається каналом у команду `sort`, яка сортує список імен за алфавітом |
| `cut -d: -f1 /etc/passwd \| sort \| more` | Ланцюжок із трьох команд: відсортований список передається в `more`, тож вивід можна переглядати по сторінках |
| `cat /etc/passwd` | Виводить увесь файл `/etc/passwd` на екран. Файл завеликий для одного екрана, тому початок виводу прокручується і не видно |
| `more /etc/passwd` | Посторінковий перегляд файлу `/etc/passwd`. Індикатор `--More--(92%)` показує, що переглянуто 92 % даних. Після досягнення кінця файлу `more` автоматично завершується |
| `h` (у `more`) | Виводить екран довідки зі списком клавіш керування (`Пробіл` - наступна сторінка, `Enter` - наступний рядок, `q` - вихід, `/вираз` - пошук, `n` - наступний збіг, `b` - назад тощо) |
| `Пробіл` (`<SPACE>`) | Перегляд наступної сторінки документа в `more` / `less` |
| `less /etc/passwd` | Посторінковий перегляд файлу командою `less`: вона має більше можливостей, ніж `more`, зокрема прокручування назад. На відміну від `more`, `less` не завершується сама в кінці файлу |
| `/bin` (у `less`) | Пошук шаблону `bin` у тексті: слеш `/` і шаблон. Екран прокручується до першого збігу |
| `n` / `N` (у `less`) | `n` - перехід до наступного збігу, `N` (велика) - до попереднього. Послідовність `nnnNNNq` - три кроки вперед, три назад і вихід |
| `q` (у `less`) | Вихід із програми `less` |
| `head /etc/passwd` | Виводить початок файлу. За замовчуванням `head` показує перші десять рядків |
| `tail /etc/passwd` | Виводить кінець файлу. За замовчуванням `tail` показує останні десять рядків |
| `head -2 /etc/passwd` | Виводить лише перші два рядки файлу. Параметр `-2` (те саме, що `-n 2`) задає кількість рядків |
| `ls /etc \| tail -5` | Вивід `ls` передається каналом у `tail`, який показує останні п'ять імен у каталозі `/etc`. Обидві команди (`head` і `tail`) можуть читати дані зі `stdin`, тобто з каналу. `head` відраховує рядки з початку даних, а `tail` - з кінця |
| `head -n -20 /etc/passwd` | Параметр `-n -#` (зі знаком мінус) виводить усі рядки, **крім** останніх `#`. Якщо у файлі 27 рядків, буде показано рядки 1-7 |
| `cd /etc` | Перехід до каталогу `/etc` (для наступних прикладів із `grep`) |
| `grep sshd passwd` | Пошук рядків, що містять послідовність символів `sshd`, у файлі `passwd`. `grep` виводить усі рядки з відповідністю, збіг підсвічується червоним. Сімейство `grep` використовує регулярні вирази |
| `grep root passwd` | Виводить усі рядки, у яких зустрічається `root`. Регулярні вирази «жадібні»: знаходяться всі входження шаблону в кожному рядку |
| `grep '^root' passwd` | Символ `^` позначає початок рядка: буде знайдено лише рядки, що починаються з `root`. Шаблони рекомендується брати в одинарні лапки, щоб оболонка не інтерпретувала спеціальні символи |
| `grep 'sync' passwd` | Пошук шаблону `sync` у будь-якому місці рядка |
| `grep 'sync$' passwd` | Символ `$` позначає кінець рядка: знаходить лише рядки, що закінчуються на `sync` |
| `grep '.y' passwd` | Символ `.` замінює будь-який один символ: шукається будь-який символ, після якого стоїть `y` |
| `grep 'sshd\|root\|operator' passwd` | Спроба знайти `sshd`, `root` або `operator`. Звичайний `grep` не сприймає `\|` як оператор «або», а шукає його як звичайний символ, тому нічого не знайдено |
| `grep -E 'sshd\|root\|operator' passwd` | Параметр `-E` вмикає розширені регулярні вирази; тепер `\|` працює як оператор альтернативи («або») і знайдено рядки з `sshd`, `root` та `operator` |
| `egrep 'no(b\|n)' passwd` | `egrep` - те саме, що `grep -E`. Дужки `( )` обмежують дію оператора `\|`, тому шукаються рядки `nob` та `non`. Без дужок шаблон `nob\|n` означав би «`nob` або `n`» |
| `head passwd \| grep '[0-9]'` | Квадратні дужки `[ ]` задають набір допустимих символів для одного символу: `[0-9]` - будь-яка цифра. `head` обмежує вивід першими десятьма рядками, які передаються на вхід `grep` |
| `grep -E '[0-9]{3}' passwd` | Фігурні дужки `{3}` вказують, що шаблон повторюється три рази, тобто шукається послідовність із трьох цифр. Для числових кванторів потрібен розширений режим `grep -E` |
