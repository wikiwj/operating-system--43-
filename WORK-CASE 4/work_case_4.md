## Завдання 1. Менеджери пакетів у Linux: основні поняття та огляд

### 1.1. Основні поняття: «пакет» та «репозиторій»

У дистрибутивах Linux на базі Debian/Ubuntu програмне забезпечення поширюється у вигляді спеціальних архівів, які називаються **пакетами**.

* **Пакет** - це заархівований файл, що містить саму програму (або її бінарні файли), інструкції з її встановлення, налаштування та метадані. Метадані включають інформацію про версію програми, опис та найголовніше — **залежності** (список інших пакетів, бібліотек або модулів, які необхідні для коректної роботи цієї програми). Пакетний менеджер автоматично перевіряє та встановлює всі відсутні залежності. У системах сімейства Debian пакети мають розширення `.deb`.

* **Репозиторій (сховище)** - це централізоване сховище (віддалений сервер або локальна директорія), де зберігаються тисячі перевірених і підписаних пакетів програмного забезпечення. Репозиторії дозволяють користувачам шукати, завантажувати, встановлювати та оновлювати програми однією командою. Система автоматично звертається до репозиторіїв, порівнює встановлені версії з актуальними та пропонує оновлення.

### 1.2. Огляд існуючих менеджерів пакетів у Linux

У Linux існує кілька рівнів управління пакетами: низькорівневі (працюють безпосередньо з `.deb` чи `.rpm` файлами) та високорівневі (керують репозиторіями, вирішують залежності тощо).

1. **APT (Advanced Package Tool)**

   * **Тип:** Високорівневий менеджер пакетів.

   * **Дистрибутиви:** Debian, Ubuntu, Linux Mint, Kali Linux та інші похідні.

   * **Можливості:** Зручний пошук пакетів у репозиторіях, автоматичне вирішення та завантаження складних залежностей, оновлення всієї операційної системи однією командою, керування зовнішніми репозиторіями (PPA). Основні утиліти — `apt`, `apt-get`, `apt-cache`.

2. **DPKG (Debian Package)**

   * **Тип:** Низкорівневий менеджер пакетів.

   * **Дистрибутиви:** Debian та похідні.

   * **Можливості:** Встановлення, видалення та керування окремими локальними файлами з розширенням `.deb`. На відміну від `apt`, `dpkg` не вміє самостійно завантажувати пакети з інтернету та розв'язувати залежності (якщо для програми потрібна бібліотека, якої немає в системі, `dpkg` видасть помилку).

3. **DNF / YUM (Dandified YUM / Yellowdog Updater, Modified)**

   * **Тип:** Високорівневий менеджер пакетів.

   * **Дистрибутиви:** Fedora, RHEL, CentOS, Rocky Linux.

   * **Можливості:** Аналогічно до APT, керує пакетами формату `.rpm`, автоматично вирішує залежності, працює з репозиторійними структурами, забезпечує оновлення системи. DNF є сучаснішою і швидшою заміною застарілого YUM.

4. **RPM (Red Hat Package Manager)**

   * **Тип:** Низкорівневий менеджер пакетів.

   * **Дистрибутиви:** Red Hat-подібні системи.

   * **Можливості:** Працює безпосередньо з окремими `.rpm` файлами (аналог `dpkg` для світу Red Hat).

5. **Pacman**

   * **Тип:** Високорівневий менеджер пакетів.

   * **Дистрибутиви:** Arch Linux та похідні (Manjaro, EndeavourOS).

   * **Можливості:** Швидкий і легкий менеджер пакетів, що працює з власними форматами архівів, підтримує репозиторії та неофіційний репозиторій AUR (Arch User Repository), де зібрано величезну кількість додатків, які компілюються під систему користувача.

6. **Універсальні менеджери пакетів (Flatpak, Snap, AppImage)**

   * **Тип:** Кросдистрибутивні менеджери ізольованих пакетів.

   * **Дистрибутиви:** Більшість сучасних дистрибутивів Linux.

   * **Можливості:** Упаковують додаток разом із усіма залежностями всередину одного контейнера, що дозволяє запускати найновіші версії програм незалежно від версій бібліотек базової операційної системи.

## 2. Менеджер пакетів мого дистрибутива та основні команди

### 2.1. Визначення менеджера пакетів

Мій дистрибутив - **Ubuntu** (віртуальна машина VirtualBox). Він належить до родини Debian/Ubuntu, тому використовує формат пакетів `.deb` та менеджер пакетів **APT** (Advanced Package Tool). Працює він у зв'язці з низькорівневою утилітою **dpkg**, яка безпосередньо встановлює та видаляє `.deb`-файли, але не вміє сама вирішувати dependencies (залежності) і завантажувати пакети.

Визначити, який менеджер використовується, можна так:

```bash
cat /etc/os-release        # назва та версія дистрибутива
which apt dpkg             # чи є apt і dpkg у системі
apt --version              # версія APT
```

### 2.2. Пошук, завантаження та встановлення пакетів

Усі команди, що змінюють систему, виконуються з правами адміністратора (`sudo`).

| Команда | Призначення |
| --- | --- |
| `sudo apt update` | Оновити локальний індекс пакетів зі сховищ (repositories), указаних у `/etc/apt/sources.list` та `/etc/apt/sources.list.d/`. Виконується **перед** установкою |
| `apt search vlc` | Пошук пакета за ключовим словом в назві та описі |
| `apt-cache search vlc` | Те саме, але через старіший інструмент `apt-cache` |
| `apt show vlc` | Докладна інформація про пакет: версія, розмір, залежності, опис, сховище |
| `apt policy vlc` | Показує, яка версія встановлена, які доступні і з якого сховища |
| `sudo apt install vlc` | Встановити пакет зі сховища за замовчуванням разом з усіма залежностями |
| `sudo apt install vlc mc htop` | Встановити кілька пакетів одночасно |
| `sudo apt install --reinstall vlc` | Перевстановити пакет |
| `apt download vlc` | Лише завантажити `.deb`-файл у поточний каталог, без встановлення |
| `sudo apt install --download-only vlc` | Завантажити пакет і залежності до кешу `/var/cache/apt/archives/`, не встановлюючи |
| `sudo apt install ./package.deb` | Встановити пакет із локального `.deb`-файлу (APT сам підтягне залежності) |
| `sudo dpkg -i package.deb` | Встановити локальний `.deb` через dpkg (залежності потрібно доставляти окремо: `sudo apt -f install`) |

**Встановлення з нового репозиторію.** Якщо потрібного пакета немає в стандартних сховищах, спочатку підключають новий repository. Загальна послідовність:

1. Завантажити та зберегти GPG-ключ сховища, щоб APT міг перевіряти підписи пакетів.
2. Додати запис про сховище у файл у каталозі `/etc/apt/sources.list.d/`.
3. Оновити індекс пакетів і встановити потрібний пакет.

```bash
# 1. Ключ репозиторію
wget -qO- https://example.com/key.asc | gpg --dearmor | sudo tee /usr/share/keyrings/example.gpg > /dev/null

# 2. Запис про репозиторій
echo "deb [signed-by=/usr/share/keyrings/example.gpg] https://example.com/repo stable main" | sudo tee /etc/apt/sources.list.d/example.list

# 3. Оновити індекс і встановити
sudo apt update
sudo apt install назва-пакета
```

Реальний приклад такого підключення (репозиторій Microsoft для Visual Studio Code) наведено в пункті 3.2. Для PPA-сховищ в Ubuntu також є команда `sudo add-apt-repository ppa:назва/ppa`.

### 2.3. Перегляд інформації про встановлені та доступні пакети

| Команда | Призначення |
| --- | --- |
| `apt list --installed` | Список усіх встановлених пакетів |
| `apt list --installed \| grep vlc` | Перевірити, чи встановлено конкретний пакет |
| `apt list --upgradable` | Пакети, для яких доступні нові версії |
| `apt list` | Усі пакети, доступні в підключених сховищах |
| `apt show vlc` | Детальна інформація про пакет |
| `dpkg -l` | Список встановлених пакетів (через dpkg) |
| `dpkg -l vlc` | Статус конкретного пакета |
| `dpkg -L vlc` | Список файлів, які встановив пакет |
| `dpkg -S /usr/bin/vlc` | З'ясувати, якому пакету належить файл |
| `apt-mark showmanual` | Пакети, які були встановлені користувачем вручну (не як залежності) |

### 2.4. Видалення непотрібних або застарілих пакетів

| Команда | Призначення |
| --- | --- |
| `sudo apt remove vlc` | Видалити пакет, **залишивши** його конфігураційні файли |
| `sudo apt purge vlc` | Видалити пакет **разом з конфігурацією** |
| `sudo apt autoremove` | Видалити пакети-залежності, які були встановлені автоматично і більше нікому не потрібні |
| `sudo apt autoremove --purge` | Те саме, разом з їх конфігураційними файлами |
| `sudo apt clean` | Очистити кеш завантажених `.deb`-файлів (`/var/cache/apt/archives/`) |
| `sudo apt autoclean` | Видалити з кешу лише застарілі версії пакетів, яких уже немає в сховищах |

### 2.5. Оновлення менеджера пакетів та системи

| Команда | Призначення |
| --- | --- |
| `sudo apt update` | Оновити **список** доступних пакетів (самі пакети не змінюються) |
| `sudo apt install --only-upgrade apt` | Оновити сам менеджер пакетів APT до нової версії |
| `sudo apt upgrade` | Оновити всі встановлені пакети до нових версій без видалення наявних пакетів |
| `sudo apt full-upgrade` | Повне оновлення: за потреби встановлює нові та видаляє конфліктні пакети (використовується, зокрема, при переході на нову версію дистрибутива) |
| `sudo apt update && sudo apt upgrade -y` | Типова зв'язка: оновити індекс і одразу всі пакети (`-y` - автоматично погоджуватись) |

## 3. Встановлення програм через менеджер пакетів

### 3.1. Новий медіаплеєр - VLC

**VLC media player** - безкоштовний кросплатформений відео- та аудіоплеєр, що відтворює більшість форматів без додаткових кодеків. Він є в стандартному сховищі Ubuntu.

```bash
sudo apt update              # оновити індекс пакетів
apt show vlc                 # переглянути інформацію про пакет (необов'язково)
sudo apt install vlc         # встановити VLC
vlc --version                # перевірити, що програму встановлено
```

Запуск: команда `vlc` у терміналі або через меню додатків.

Видалення (за потреби): `sudo apt purge vlc && sudo apt autoremove`.

### 3.2. Середовище для програмування - Visual Studio Code

**Visual Studio Code** (VS Code) відсутній у стандартних репозиторіях Ubuntu, тому його встановлюють з офіційного репозиторію Microsoft. Це приклад підключення нового сховища з пункту 2.2.

**Спосіб 1. Через репозиторій Microsoft (рекомендований, програма оновлюється разом із системою):**

```bash
# 1. Залежності
sudo apt update
sudo apt install -y wget gpg apt-transport-https

# 2. GPG-ключ Microsoft
wget -qO- https://packages.microsoft.com/keys/microsoft.asc | gpg --dearmor > microsoft.gpg
sudo install -D -o root -g root -m 644 microsoft.gpg /usr/share/keyrings/microsoft.gpg
rm -f microsoft.gpg

# 3. Додати репозиторій
sudo tee /etc/apt/sources.list.d/vscode.sources > /dev/null << 'EOF'
Types: deb
URIs: https://packages.microsoft.com/repos/code
Suites: stable
Components: main
Architectures: amd64,arm64,armhf
Signed-By: /usr/share/keyrings/microsoft.gpg
EOF

# 4. Оновити індекс і встановити
sudo apt update
sudo apt install -y code

# 5. Перевірка
code --version
```

**Спосіб 2. Через завантажений `.deb`-пакет** (завантажити з офіційного сайту code.visualstudio.com):

```bash
sudo apt install ./code_*.deb
```

**Спосіб 3. Через snap (у Ubuntu встановлений за замовчуванням):**

```bash
sudo snap install code --classic
```

Запуск: команда `code` у терміналі або через меню додатків.

**Компілятор C++.** Оскільки VS Code - це лише редактор, для мови C++ додатково потрібен компілятор. Встановлюється пакетом `build-essential`:

```bash
sudo apt install build-essential    # gcc, g++, make, інші інструменти збірки
g++ --version                       # перевірка
```

## 4. Встановлення програм через графічний інтерфейс (GUI)

Встановлювати програми в Linux можна через термінал або за допомогою графічного інтерфейсу. Для цього є магазини додатків і графічні менеджери пакетів.

1. **Магазини додатків (App Stores)**. У них можна шукати програми, переглядати їхні описи та встановлювати потрібний софт.
2. **Графічні менеджери пакетів (GUI package managers)**. Вони дозволяють встановлювати та видаляти програми, а також працювати з окремими пакетами й бібліотеками.

---

### 4.1. Встановлення через магазин додатків (Ubuntu App Center / GNOME Software)

В Ubuntu є **App Center** (раніше називався Ubuntu Software). Через нього можна знаходити та встановлювати програми з репозиторіїв APT і каталогу Snap Store.

**Процес встановлення:**

1. Відкриваємо **App Center** через меню програм або панель Dock.
2. У рядку пошуку вводимо назву потрібної програми, наприклад `GIMP` або `Telegram`.
3. Відкриваємо сторінку програми. Якщо доступно кілька джерел встановлення, можна вибрати потрібне, наприклад Snap або deb-пакет.
4. Натискаємо кнопку **Install** ("Встановити").
5. Якщо система запитує пароль, вводимо пароль свого користувача для підтвердження встановлення.
6. Чекаємо завершення завантаження та встановлення. Після цього програму можна відкрити через кнопку **Open** ("Відкрити").

**Приклад:**

* Встановлення **GIMP**, графічного редактора для роботи із зображеннями. Для цього достатньо знайти програму через App Center і натиснути кнопку встановлення.

---

### 4.2. Встановлення через графічні менеджери пакетів

Магазини додатків не завжди показують усі системні утиліти, бібліотеки та кодеки. Для роботи з такими пакетами можна використовувати графічні менеджери. Вони дають змогу переглядати доступні пакети, перевіряти залежності та керувати встановленням програм.

#### 1. Synaptic Package Manager

**Synaptic** є графічним менеджером пакетів для системи APT. Він показує пакети, доступні в підключених репозиторіях, і дозволяє встановлювати, оновлювати та видаляти програми й бібліотеки.

Якщо Synaptic ще не встановлений, відкриваємо термінал і вводимо команду:

```bash
sudo apt install synaptic -y
```

**Процес встановлення через Synaptic:**

1. Запускаємо Synaptic. Програма може запросити пароль адміністратора.
2. Натискаємо кнопку **Search** ("Пошук") на панелі інструментів і вводимо назву потрібної програми, наприклад `gparted`, яка використовується для роботи з розділами дисків.
3. У списку знайдених пакетів натискаємо правою кнопкою миші на потрібний пакет і вибираємо **Mark for Installation** ("Позначити для встановлення").
4. Якщо для роботи програми потрібні додаткові пакети, Synaptic покаже вікно зі списком залежностей. Перевіряємо список і натискаємо **Mark**, щоб підтвердити вибір.
5. Натискаємо кнопку **Apply** ("Застосувати") на верхній панелі. Перевіряємо список змін і підтверджуємо встановлення.
6. Synaptic завантажує потрібні пакети, встановлює їх і повідомляє про завершення процесу.

**Приклад:**

* Встановлення **GParted** разом із необхідними бібліотеками для роботи з файловими системами.

#### 2. GDebi Package Installer

Іноді програми можна завантажити із сайтів розробників у вигляді файлів із розширенням `.deb`. Наприклад, такі пакети використовуються для встановлення Google Chrome, Discord та інших програм.

Для встановлення цих файлів можна використовувати **GDebi Package Installer**. Ця програма перевіряє залежності пакета та допомагає встановити його в систему.

Щоб встановити GDebi, відкриваємо термінал і вводимо команду:

```bash
sudo apt install gdebi -y
```

**Процес використання:**

1. Завантажуємо `.deb`-файл із сайту розробника, наприклад `google-chrome-stable_current_amd64.deb`.
2. Натискаємо на завантажений файл правою кнопкою миші.
3. Вибираємо **Open With Other Application** ("Відкрити за допомогою іншої програми") та запускаємо файл через **GDebi Package Installer**.
4. Програма перевіряє пакет і показує інформацію про його залежності. Так можна побачити, чи є в системі необхідні компоненти для встановлення.
5. Натискаємо **Install Package** ("Встановити пакет"). Якщо система запитує пароль адміністратора, вводимо його.
6. Чекаємо завершення встановлення.

GDebi зручний у випадках, коли потрібно встановити окремий deb-файл, завантажений вручну, а не шукати програму в магазині додатків.

### 4.3. Порівняння способів встановлення в GUI

| Інструмент | Для чого використовується | Переваги | Недоліки |
|---|---|---|---|
| **Ubuntu App Center** | Встановлення звичайних програм, наприклад браузерів, плеєрів і месенджерів | Простий інтерфейс, зручний пошук, описи програм та автоматичні оновлення | Не всі системні пакети доступні через інтерфейс, часто пропонуються Snap-пакети |
| **Synaptic** | Встановлення системних утиліт, бібліотек та керування пакетами | Дозволяє переглядати доступні пакети, залежності та вибирати потрібні компоненти | Інтерфейс може бути складним для новачків, немає зображень програм |
| **GDebi** | Встановлення окремих `.deb`-файлів, завантажених із сайтів | Перевіряє залежності та допомагає встановлювати локальні пакети | Не призначений для пошуку програм у репозиторіях |
