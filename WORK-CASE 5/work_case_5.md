## Завдання 1. Підключення периферійного обладнання в Linux: принтер, флешка та операція монтування

### 1.1. Загальний механізм роботи Linux з периферійними пристроями

В ОС Linux діє базовий принцип **«все є файлом»**. Кожен пристрій (диск, флешка, клавіатура, принтер) представлений у системі спеціальним **файлом пристрою**, який зберігається в каталозі `/dev`. Завдяки цьому програми працюють з обладнанням через стандартні операції читання та запису, не знаючи деталей його апаратної реалізації.

Підключення будь-якого пристрою проходить кілька етапів:

1. **Виявлення апаратури.** Ядро (kernel) отримує сигнал від шини (USB, SATA тощо) про підключення нового пристрою та зчитує його ідентифікатори (Vendor ID, Product ID, клас пристрою).

2. **Завантаження драйвера.** Драйвери в Linux - це модулі ядра (`.ko`). Ядро підбирає відповідний модуль за ідентифікаторами та завантажує його. Наприклад, для USB-принтера це `usblp`, для флешки - `usb-storage` або `uas`.

3. **Створення файлу пристрою.** Сервіс **udev** (менеджер пристроїв) отримує подію від ядра, створює вузол у `/dev` (наприклад, `/dev/sdb1` або `/dev/usb/lp0`), призначає права доступу та за потреби запускає додаткові дії за правилами з `/etc/udev/rules.d/`.

4. **Використання пристрою.** Залежно від типу пристрою система передає його відповідній службі: для принтера - системі друку **CUPS**, для флешки - механізму **монтування** файлової системи.

### 1.2. Підключення принтера

Для роботи з принтерами в Linux використовується система друку **CUPS (Common Unix Printing System)**. Вона складається з кількох компонентів:

* **Демон `cupsd`** - фонова служба, що приймає завдання на друк, ставить їх у чергу та керує ними. Веб-інтерфейс доступний за адресою `http://localhost:631`.

* **Драйвер принтера (PPD-файл)** - файл опису можливостей конкретної моделі (роздільна здатність, формат паперу, двосторонній друк тощо). Для багатьох сучасних принтерів використовується режим «driverless» (IPP Everywhere), коли встановлення драйвера не потрібне.

* **Фільтри** - програми, що перетворюють документ (PDF, текст, зображення) у формат, зрозумілий принтеру (PostScript, PCL, растр).

* **Backend** - модуль, який передає підготовлені дані на пристрій через потрібний інтерфейс: `usb`, `ipp`, `socket`, `lpd`.

**Послідовність роботи при друку:**

1. Користувач надсилає документ на друк (команда `lp` або кнопка «Друк» у програмі).
2. CUPS створює завдання (job) та поміщає його в чергу.
3. Фільтри перетворюють документ у формат, який розуміє принтер.
4. Backend передає дані на принтер через USB, мережу або інший інтерфейс.
5. Принтер друкує, а CUPS отримує статус виконання.

**Основні команди:**

```bash
lpinfo -v                                   - список доступних пристроїв друку
lpstat -p -d                                - стан принтерів та принтер за замовчуванням
sudo lpadmin -p MyPrinter -E -v usb://... -m everywhere   - додати принтер
lp -d MyPrinter document.pdf                - надіслати файл на друк
lpq                                         - переглянути чергу друку
lprm 12                                     - скасувати завдання №12
```

Важливо, що принтер **не монтується**: він не містить файлової системи, тому для нього використовується не монтування, а черга друку та драйвер.

### 1.3. Підключення флешки

Флешка - це **блоковий пристрій** зі своєю файловою системою (FAT32, exFAT, NTFS, ext4 тощо). Після підключення відбувається таке:

1. Ядро визначає USB-накопичувач і завантажує драйвер `usb-storage`/`uas`.
2. Накопичувач отримує ім'я у `/dev`: наприклад, `/dev/sdb`, а його розділи - `/dev/sdb1`, `/dev/sdb2` тощо.
3. Сервіс **udev** створює файл пристрою та додаткові символьні посилання (за міткою, UUID) у `/dev/disk/by-label/`, `/dev/disk/by-uuid/`.
4. У графічних середовищах (GNOME, KDE) служба **udisks2** автоматично **монтує** флешку, зазвичай у каталог `/media/<користувач>/<мітка>` або `/run/media/<користувач>/<мітка>`. У мінімальних системах і на серверах монтування виконується вручну.

Поки файлова система не змонтована, користувач не бачить на флешці файлів і папок: у системі є лише «сирий» блоковий пристрій `/dev/sdb1`.

**Команди для перегляду пристроїв:**

```bash
lsblk              - дерево блокових пристроїв і точок монтування
lsblk -f           - з типами файлових систем, мітками та UUID
sudo blkid         - ідентифікатори та типи файлових систем
sudo fdisk -l      - таблиці розділів
dmesg | tail       - повідомлення ядра про підключення пристрою
lsusb              - список USB-пристроїв
```

### 1.4. Суть операції монтування

**Монтування (mounting)** - це операція підключення файлової системи окремого пристрою або розділу до єдиного дерева каталогів операційної системи через певний каталог, який називається **точкою монтування (mount point)**.

На відміну від Windows, де кожен диск має власну літеру (`C:`, `D:`, `E:`), у Linux існує **єдине дерево каталогів** з коренем `/`. Усі диски, розділи та флешки стають частиною цього дерева. Після монтування вміст пристрою відображається всередині точки монтування, і з ним можна працювати як зі звичайним каталогом.

**Для чого використовується монтування:**

* Надає доступ до файлової системи пристрою (флешки, жорсткого диска, DVD, ISO-образу, мережевої папки).
* Забезпечує єдиний спосіб доступу до даних незалежно від типу носія та файлової системи.
* Дозволяє розділити систему на частини (наприклад, `/home`, `/var` або `/boot` на окремих розділах).
* Дає змогу керувати параметрами доступу: лише читання (`ro`), заборона запуску програм (`noexec`) тощо.
* Дозволяє підключати мережеві ресурси (NFS, Samba/CIFS) так, ніби вони розташовані локально.

**Як виконується монтування вручну:**

1. Визначити ім'я пристрою:

```bash
lsblk
```

2. Створити точку монтування (порожній каталог):

```bash
sudo mkdir -p /mnt/usb
```

3. Змонтувати файлову систему:

```bash
sudo mount /dev/sdb1 /mnt/usb
```

   За потреби можна вказати тип файлової системи та параметри:

```bash
sudo mount -t vfat -o ro,uid=1000 /dev/sdb1 /mnt/usb
```

4. Працювати з файлами в каталозі `/mnt/usb`:

```bash
ls /mnt/usb
cp report.txt /mnt/usb/
```

5. Перед фізичним вилученням флешки **обов'язково відмонтувати** її:

```bash
sync                    - записати незбережені дані з кешу на пристрій
sudo umount /mnt/usb    - відмонтувати (можна також: umount /dev/sdb1)
```

Якщо команда `umount` повертає помилку «target is busy», це означає, що якась програма використовує файли на флешці. Побачити такі процеси можна командою `lsof /mnt/usb` або `fuser -vm /mnt/usb`.

**Чому відмонтування важливе:** Linux використовує кеш у пам'яті для прискорення операцій запису. Якщо вийняти флешку без відмонтування, частина даних може бути не записана, що призведе до втрати файлів або пошкодження файлової системи.

**Автоматичне монтування при завантаженні** налаштовується у файлі `/etc/fstab`. Кожен рядок містить шість полів:

```text
# <пристрій>              <точка>     <тип>   <параметри>        <dump> <pass>
UUID=1234-ABCD            /mnt/usb    vfat    defaults,nofail    0      0
```

Для надійності в `fstab` краще використовувати **UUID**, а не ім'я `/dev/sdb1`, оскільки ім'я пристрою може змінюватися залежно від порядку підключення. Перевірити запис без перезавантаження можна командою `sudo mount -a`. Поточні змонтовані файлові системи виводяться командами `mount`, `findmnt` та `df -h`.

### 1.5. Порівняння підключення принтера та флешки

| Критерій | Принтер | Флешка |
|---|---|---|
| Тип пристрою | Символьний пристрій / мережевий пристрій друку | Блоковий пристрій |
| Файл у `/dev` | `/dev/usb/lp0` (для USB) | `/dev/sdb`, `/dev/sdb1` |
| Драйвер | `usblp` та PPD-файл (або driverless) | `usb-storage` / `uas` та драйвер файлової системи |
| Керуюча служба | CUPS (`cupsd`) | udev, udisks2 |
| Наявність файлової системи | Немає | Є (FAT32, exFAT, NTFS, ext4) |
| Потрібне монтування | Ні | Так |
| Основні команди | `lpinfo`, `lpadmin`, `lp`, `lpstat` | `lsblk`, `mount`, `umount`, `blkid` |

| **File System** | Файлова система - спосіб організації та зберігання файлів і каталогів на носії (ext4, FAT32, NTFS). |
| **Mount** | Монтування - підключення файлової системи пристрою до дерева каталогів ОС. |

| **Unmount** | Відмонтування - від'єднання файлової системи від дерева каталогів із записом усіх даних на носій. |
| **fstab** | Файл `/etc/fstab` - таблиця файлових систем, що монтуються автоматично під час завантаження. |
| **UUID** | Universally Unique Identifier - унікальний ідентифікатор розділу, що не змінюється при перепідключенні. |

# Гапонюк Назар:

## Завдання 1 (продовження). Відмінності роботи з периферією в ОС Linux та ОС Windows

Основна ідея Linux - **єдина файлова модель**: кожен пристрій має файл у `/dev`, а всі файлові системи підключаються до одного дерева каталогів. У Windows пристрої представлені через **диспетчер пристроїв**, а диски отримують **літери** (`C:`, `D:`, `E:`). Нижче наведено порівняння за основними критеріями.

| Критерій | ОС Linux | ОС Windows |
| --- | --- | --- |
| Представлення пристроїв | файли в `/dev` (`/dev/sdb1`, `/dev/usb/lp0`); працюють звичайні операції читання й запису | об'єкти пристроїв, що керуються через «Диспетчер пристроїв» та драйвери |
| Адресація дисків | єдине дерево з коренем `/`; носій доступний через точку монтування (`/media/...`, `/mnt/...`) | кожен розділ або флешка отримує окрему літеру диска |
| Монтування | явна операція `mount` / `umount`; в графічному середовищі виконується автоматично службою udisks2 | виконується приховано: літера призначається автоматично, окремої операції користувач не бачить |
| Драйвери | більшість драйверів вже входить до ядра або є його модулями (`.ko`), підключаються автоматично за ID пристрою | драйвери підвантажуються з Windows Update або встановлюються з пакета виробника (`.inf`, `.sys`, `.exe`) |
| Друк | система друку CUPS, формат PPD, режим driverless (IPP Everywhere); керування через `lpadmin`, `lp`, веб-інтерфейс `localhost:631` | служба Print Spooler, драйвер принтера від виробника, керування через «Параметри» → «Принтери» |
| Файлові системи флешок | ext4, FAT32, exFAT, NTFS та інші; для NTFS є драйвери `ntfs3` / `ntfs-3g` | NTFS, FAT32, exFAT; ext4 без додаткового ПЗ не підтримується |
| Безпечне вилучення | `sync` і `umount` (або «Витягнути» у файловому менеджері) | «Безпечне видалення пристрою» в треї |
| Права доступу | права власника/групи/інших (`rwx`), параметри `uid`, `gid`, `ro`, `noexec` при монтуванні | списки контролю доступу (ACL) NTFS |
| Автоматизація | скрипти, `udev`-правила, `/etc/fstab` | політики, планувальник завдань, PowerShell |
| Діагностика | `lsusb`, `lsblk`, `dmesg`, `lspci`, `journalctl` | «Диспетчер пристроїв», «Керування дисками», журнал подій |
| Відкритість | відкритий код ядра й драйверів, можна змінювати правила та параметри | драйвери переважно закриті, поведінка визначається виробником |

**Висновок до порівняння.** У Linux робота з периферією більш прозора й гнучка: усе керується файлами та текстовими налаштуваннями, а більшість обладнання працює без встановлення додаткових драйверів. У Windows процес більш автоматизований для користувача, але залежить від драйверів виробника та має менше засобів тонкого налаштування.

## Завдання 2. Підключення флешки та принтера до віртуальної машини Ubuntu

### 2.1. Умови виконання

* Гостьова ОС: **Ubuntu** (графічне середовище GNOME), встановлена на віртуальній машині.
* Пристрої: USB-флешка (файлова система FAT32, мітка `USB_FLASH`) і USB-принтер HP LaserJet P1102.
* На флешці підготовлено два файли: `lab_gui.pdf` (для копіювання через графічний інтерфейс) та `lab_term.pdf` (для копіювання через термінал).

### 2.2. Підключення пристроїв до віртуальної машини

Віртуальна машина за замовчуванням не бачить USB-пристрої хост-системи, тому їх потрібно «пробросити» (USB passthrough):

1. У налаштуваннях віртуальної машини (наприклад, VirtualBox) увімкнути USB-контролер: **Settings → USB → Enable USB Controller** (для USB 2.0/3.0 потрібен встановлений Extension Pack).
2. Підключити флешку та принтер до комп'ютера.
3. У запущеній віртуальній машині в меню **Devices → USB** поставити позначки навпроти флешки та принтера (або додати їх у фільтри USB, щоб вони підключалися автоматично). Після цього пристрої відключаються від хост-системи й передаються гостьовій ОС.
4. У гостьовій Ubuntu перевірити, що пристрої виявлено:

```bash
lsusb
```

```text
Bus 001 Device 005: ID 03f0:002a HP, Inc HP LaserJet P1102
Bus 001 Device 004: ID 0951:1666 Kingston Technology DataTraveler 100 G3
```

```bash
lsblk -f
```

```text
NAME   FSTYPE FSVER LABEL     UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
sda
└─sda1 ext4   1.0             5f2c1a7e-3b1d-4c0e-9f7a-2d8e6b4a1c33   35.2G    28% /
sdb
└─sdb1 vfat   FAT32 USB_FLASH 1A2B-3C4D                              14.2G     9% /media/student/USB_FLASH
```

Рядок `sdb1` з типом `vfat` та точкою монтування `/media/student/USB_FLASH` показує, що флешку розпізнано й змонтовано автоматично. Додатково можна переглянути повідомлення ядра:

```bash
dmesg | tail
```

```text

usb-storage 1-1:1.0: USB Mass Storage device detected
sd 2:0:0:0: [sdb] Attached SCSI removable disk
usblp 1-2:1.0: usblp0: USB Printer Device
```

### 2.3. Підключення принтера в системі

1. Відкрити **Settings → Printers** (Параметри → Принтери).
2. Принтер з'являється в списку автоматично (CUPS виявляє його по USB). Якщо його немає, натиснути **Add Printer…** і вибрати пристрій зі списку.
3. Задати принтер за замовчуванням і за потреби надрукувати тестову сторінку (**Printing Options → Print Test Page**).

Перевірка через термінал:

```bash
lpstat -p -d
```

```text
printer HP_LaserJet_P1102 is idle.  enabled since Fri 23 Oct 2026 12:10:04 PM EEST
system default destination: HP_LaserJet_P1102
```

### 2.4. Копіювання та друк через графічний інтерфейс

1. Відкрити файловий менеджер **Files** (Nautilus). У лівій панелі з'явився пристрій `USB_FLASH`: Ubuntu змонтувала його автоматично (служба udisks2) у каталог `/media/student/USB_FLASH`.
2. Відкрити флешку, знайти файл `lab_gui.pdf`, виділити його й виконати **Copy** (`Ctrl+C`).
3. Перейти в каталог **Documents** на віртуальній машині та вставити файл (`Ctrl+V`).
4. Відкрити скопійований файл подвійним клацанням (програма **Document Viewer**).
5. Вибрати **Print** (`Ctrl+P`), у списку вказати принтер `HP LaserJet P1102`, задати кількість копій (1) та натиснути **Print**.
6. Переконатися, що завдання виконується: принтер друкує сторінку, а в `lpq` або в налаштуваннях принтера черга порожня.
7. Після завершення роботи з флешкою натиснути значок **Eject** (витягнути) поруч із назвою `USB_FLASH` у файловому менеджері. Це виконує відмонтування.

### 2.5. Копіювання та друк через термінал

Для демонстрації повного циклу роботи вручну відмонтуємо флешку, змонтуємо її у власний каталог і виконаємо всі дії командами.

**Крок 1. Визначити пристрій та поточну точку монтування:**

```bash
lsblk -f
```

Флешка - `/dev/sdb1`, файлова система `vfat`.

**Крок 2. Відмонтувати автоматичне монтування:**

```bash
sudo umount /dev/sdb1
```

**Крок 3. Створити точку монтування й змонтувати флешку:**

```bash
sudo mkdir -p /mnt/usb
sudo mount -o uid=$(id -u),gid=$(id -g) /dev/sdb1 /mnt/usb
```

Параметри `uid` та `gid` для FAT32 роблять власником файлів поточного користувача, тому записувати й копіювати можна без `sudo`.

**Крок 4. Переглянути вміст флешки та перевірити монтування:**

```bash
ls -l /mnt/usb
findmnt /mnt/usb
```
